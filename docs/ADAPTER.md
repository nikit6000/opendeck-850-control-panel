# STM32F401 adapter: stands in for the MAIN board on the CDJ-850 panel bus

**Works (checked 2026-11-10):** MAIN unplugged, the panel exchanges frames with the adapter just as it does with the native MAIN.
- The panel frames arrive: buttons, jog, fader. The panel acknowledges our screen frame (byte 9) and echoes our heartbeat (byte 11).
- With a host player program, a button press goes to the host and the lamp comes back.

The adapter does the timing-critical part itself. The host (Mac / Pi) exchanges complete frames with it over USB.

## How the bus works ([PROTOCOL.md](PROTOCOL.md))

- **The panel provides the clock** (TSCK, ~1.3 MHz, SPI mode 3, LSB first, 16-byte frame every 0.755 ms). MAIN only answers on TSO.
- **Start handshake.** After power-on (PWR_ON), MAIN_XBUSY must be high ("MAIN busy/booting") and then go low ("ready").
  - Until that happens, the panel does not clock and shows **E-8709**.
  - The adapter holds MAIN_XBUSY high for 2.8 s after PWR_ON, then pulls it low.
- **Frames** follow the native MAIN's cycle: `02, x, x, 01, x, x`.
  - `01` and `02` (lamps, numbers, indicators) come from the host.
  - `x` cycles through the other frames: 80 screen, 81/82 text, 60 heartbeat. The heartbeat is generated by the adapter (+1 every 20 ms).
  - Until the host connects, the adapter sends the native MAIN's no-media frames. Checksums are computed by the adapter.

## Wiring

Everything goes **through 1 kΩ in series**.
- The bus is 3.3 V (measured on TSI), so no level shifting is needed.
- **⚠ CN2007 pin 1 = +12 V. Don't touch it.**

| signal | where | → Black Pill | role |
|---|---|---|---|
| GND | CN2007 pin 2 | G | |
| TSCK | CN2007 pin 5 | A5 + B13 + A15 | panel clock: SPI1, SPI2, frame-end timer |
| TSI (panel → MAIN) | CN2007 pin 6 | B15 | SPI2 MOSI: panel frames |
| TSO (MAIN → panel) | CN2007 pin 8 | **B14** (output) + A7 (read-back) | SPI2 MISO: our answer; SPI1: what is really on the line |
| PNL_XBUSY | CN2007 pin 7 | B0 | logged (MASTER waits on it) |
| PWR_ON | CN2007 pin 9 | **A1** | MAIN_XBUSY timing is counted from it |
| MAIN_XBUSY | CMPX CN2002 pin 12 (MAIN shroud) or CN2003 pin 10 | **B1** | handshake: high → low |

- The native MAIN must be **unplugged** (the 27P FFC CN2002 ⇄ CN402). Otherwise it fights us on TSO and MAIN_XBUSY.
- The panel still needs its supply rails (V+5R6, V+12_EUP via the same FFC); in the test setup they still came from the main board's power section.
- The Black Pill is powered from USB (the Mac).

## Modes (cmd 0x03)

| mode | what the adapter does | when |
|---|---|---|
| 0 LISTEN (default after reset) | only listens: both SPIs are receivers, B1/B14 are not driven | native MAIN is connected, sniffing |
| **2 SLAVE** | stands in for MAIN: MAIN_XBUSY handshake, answers each panel frame on B14 | **working mode** without MAIN |
| 1 MASTER | drives TSCK itself (SPI1 master, 1.3125 MHz) and waits on PNL_XBUSY | not needed for the CDJ-850 panel (it clocks itself); kept for experiments |

A repeated command with the same mode does not restart the handshake. Switching modes does.

## Firmware

```bash
cd firmware
./build.sh          # → adapter.bin + ELF (Rust, thumbv7em; rustup from Homebrew)
./flash.sh          # ST-Link via probe-rs (brew install probe-rs-tools); ./flash.sh dfu — via USB DFU
```

- With an ST-Link V2 clone on macOS, st-flash and openocd hung (libusb); probe-rs works fine.
- The chip is not detected automatically; flash.sh passes `--chip STM32F401CCUx`.
- After a reset the board shows up as `/dev/cu.usbmodem*` (USB 1209:0850, "CDJ-850 panel bus adapter").
- The crystal is assumed to be **25 MHz** (Black Pill).
- After flashing, the adapter comes up in LISTEN. The panel will hit E-8709 until the host sets SLAVE mode and the player is power-cycled.
  - Exception: if PWR_ON is already high, the handshake runs immediately when SLAVE is set, and the panel picks up without a power cycle.

## Use

```bash
pip install pyserial numpy
python3 host/sniff.py --slave --stats      # stand in for MAIN, stats per second
python3 host/sniff.py --slave              # changes: buttons, text
python3 host/sniff.py                      # LISTEN: sniffer with the native MAIN
```

- `sniff.py --save x.npy` writes `(t, TSI, TSO, flags)`. The first three fields match the layout of `tools/saleae/decode.py`, so `tools/saleae/diff.py` and `host/tlv.py` work on it.
- A host program talks to the adapter with the USB protocol below: put the adapter in SLAVE mode (cmd 0x03 = 2), send frames 01/02 (cmd 0x01) whenever lamps or numbers change, read panel frames from the records.

## USB protocol

Device → host, 44-byte record per bus frame:
`A5 5A | seq u16 | t_us u32 | n_tso | n_tsi | flags | dropped | TSO[16] | TSI[16]`.
- flags: bit0 PNL_XBUSY, bit1 MAIN_XBUSY, bit2 MASTER, bit3 PWR_ON, bit4 SLAVE.

Host → device: `A5 5A | cmd | len | payload`:
| cmd | len | meaning |
|---|---|---|
| 0x01 | 32 | MAIN frames 0x01 and 0x02 (byte 15 is ignored; the checksum is computed by the adapter) |
| 0x02 | 16·k | other frames in send order (80, 81…, 70…); 0x60 is added if missing |
| 0x03 | 1 | mode 0 / 1 / 2 (see above) |

## Inside the firmware

- **SPI2** is a slave on the panel's clock.
  - RX: TSI → DMA1 S3.
  - In SLAVE mode, TX: answer → DMA1 S4 → MISO (B14).
- **SPI1** is a receiver on the TSO line (LISTEN/SLAVE) or the master (MASTER).
- **TIM2** is in reset mode on TSCK (A15). 40 µs of clock silence marks the end of a frame. The interrupt then:
  - hands the frame to USB;
  - resets the slave SPIs (bit alignment starts fresh);
  - loads the next answer. There are ~600 µs left before the next frame.
- **TIM3** runs at 10 µs: the MAIN_XBUSY handshake from PWR_ON, and the MASTER-mode scheduler.
